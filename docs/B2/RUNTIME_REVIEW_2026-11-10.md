Решение — отдельно доставляемый far-JSON + укрупнённый batching на обзоре; плотность исходных деревьев ради этого не снижать.**

### 2. Конкретное решение по LOD

**Две доставляемые репрезентации, без нового бинарного формата:**

- **Full:** существующий детальный JSON; загружать только для близкой области.
- **Far:** отдельный компактный JSON на те же 437 адресов, генерируемый офлайн. Обзор не должен скачивать, разбирать или строить full.
- **Обзорные render-группы:** объединять far примерно по **4 × 4 исходных тайла**, сохраняя исходную адресацию. Это десятки групп вместо сотен отдельных наборов draw calls. Новая сетка хранения пока не нужна.

**Состав far:**

| Слой | Представление |
|---|---|
| Здания | Упрощённые footprint-extrusions с сохранением высоты, цвета и характерных силуэтов; без оконной геометрии и мелких частей |
| Растительность | Маска плотности/цвета на земле + редкие объёмные группы крон; не 1,91 млн индивидуальных экземпляров |
| Дороги, вода, земля | Обзорный растр без мелкой разметки; сохранять читаемость магистралей, воды, лесов и ВПП |
| Мосты/эстакады | Упрощённый объём там, где плоский растр теряет пространственную связь |
| Landmark’и | Отдельно защищённые силуэты; не превращать в обычные коробки |

Промежуточный масштаб сначала обслуживать far с достаточной детализацией. Третью доставляемую ступень добавлять только при доказанном визуальном провале.

**Обязательная часть стримера:** байтовый admission control **до** fetch/build/upload, ограниченные очереди, отмена устаревших задач и учёт временного far/full-сосуществования. Число `400` не заменять на `437` как «исправление».

При переходах исключать двойную отрисовку заменённой территории. Обновлять только затронутую обзорную группу, не пересобирать весь город.

### 3. Бюджеты: предлагаемые ворота, не обещание FPS

Для **той же RTX 3080 Laptop**, фиксированных viewport, render scale, стиля, света и pixel-art режима:

| Метрика | Полный обзор | Близкий вид с дальним окружением |
|---|---:|---:|
| Уникальные видимые треугольники основной сцены | цель ≤1 млн; предел **1,5 млн** | предел **3 млн** |
| Draw calls основной сцены | **≤200** | **≤350** |
| Все проходы кадра | **≤400 draws** | **≤600 draws** |
| Учтённые резидентные ресурсы | **≤200 МиБ** | **≤450 МиБ** |
| Пик при замене LOD | colspan | **≤600 МиБ суммарно** |
| Производительность в движении | **p95 frame time ≤33 мс** | **p95 ≤22 мс**, цель 60 FPS |

Пик 600 МиБ относится к обоим сценариям; считать текстуры, буферы, общие ресурсы и временные замены, а не только нынешний `geometryMB`.

Это требует относительно нынешних **отрисованных** 50 млн треугольников примерно **порядка величины сокращения и более**. Точный коэффициент определим после разделения проходов. **Линейного пересчёта треугольников в FPS нет:** старые 4 FPS уже показывают, что одних геометрических лимитов недостаточно.

Дополнительные предлагаемые ворота:
- полный обзор: **≤10 с cold / ≤3 с warm** на локальном сервере, отдельно от сетевого теста;
- целевой суммарный far-body **≤20 МиБ несжатого JSON**; фактический HTTP-transfer фиксировать отдельно;
- после пяти циклов обзор → центр → Липки → обзор ресурсы возвращаются в пределах **10% от прогретого состояния**, без монотонного роста.

### 4. Деревья: не снижать плотность «за старой рамкой»

**Сохраняем 1,91 млн в full-кандидате.** Граница прежних 12 км не должна становиться границей качества.

Но `trees_budget_scale = 1` означает лишь отсутствие **глобального** прореживания. Уже удалено **52 614** деревьев per-tile cap. До окончательной приёмки нужны:
- карта потерь по тайлам и доля потерь;
- подтверждение сохранности mapped-деревьев;
- близкие кадры наиболее затронутых лесов и кладбища.

Не поднимать cap вслепую и не регенерировать весь датасет сейчас. Если cap создаёт видимые прямоугольные разрежения, исправлять локальную политику генерации, а не маскировать это far.

### 5. Следующий исполняемый шаг и переключение

**Сейчас — LOD-прототип, не финальная полировка края.**

1. Свести счётчики, разбить runtime-стоимость по слоям/проходам; подтвердить восстановление рабочих файлов после временной подмены.
2. Собрать far на репрезентативных зонах: плотный центр, лес, вода/мост, Липки. Review: payload/build/upload, силуэты, растительность, день/ночь.
3. Распространить far на 437 адресов; включить batching и байтовые бюджеты. На обзорном cold start **ноль запросов full**.
4. Пройти runtime-ворота, затем финально принять края, Липки, камеру и переходы масштаба.

Проверки **полноты данных и отсутствия обрезанных обязательных объектов** продолжаются сейчас; художественное оформление края — после получения управляемого обзора.

**Переключение разрешать только вместе:** полный охват без подложки вместо города, принятые близкие виды, бюджеты/тайминги, отсутствие утечек и дыр при переходах, сохранность рабочих данных и отдельный визуальный sign-off. Headless-замер оставить воспроизводимым тестом; юзабельность дополнительно подтвердить в обычном интерактивном браузере.
