# Модели транспорта — Blender и фоновые поезда

Дата: 18 ноября 2026. Ветка: `codex/public-transport-signals`.

Транспорт на карте больше не строится только процедурно: семь low-poly
шаблонов авторятся в Blender, экспортируются в компактный бинарный payload и
подменяют процедурные fallback-модели при старте. Ливреи взяты с фотографий
реальных минских машин, а не выбраны «по вкусу».

семь шаблонов. Оси: +X вперёд, +Y вверх, +Z вправо; низ колёс на `y = 0`,
модель центрирована по длине.

Детализация: скошенный кузов, длинная тёмная полоса остекления с

пантограф, тележки, буферы, межвагонные гармошки, рёбра полувагона.

### Сборка

```powershell
# модели + runtime payload (assets/transport/*.blend и vehicles.bin)
pnpm run models:transport

# то же + Cycles-превью в screenshots/transport-models/
pnpm run models:transport:preview

# извлечь ж/д пути из принятых тайлов
pnpm run data:rail
```

`BLENDER_EXE` переопределяет путь к Blender; по умолчанию используется
`C:\Program Files\Blender Foundation\Blender 5.1\blender.exe`.

Скрипт падает, если треугольники/габариты/низ модели выходят за бюджет —
модель не может незаметно «разрастись».

## Payload

`public/data/mobility/vehicles/manifest.json` + `vehicles.bin`:

- non-indexed triangle soup, плоские нормали считаются при загрузке;
- `int16` x/y/z в сантиметрах (`positionScale = 100`), runtime-оси
  +X вперёд / +Y вверх / +Z вправо;
- `uint8` sRGB, по 3 байта на вершину, сразу после массива позиций;
- manifest содержит `vertexStart`, `vertexCount`, `triangles`, `bounds` и
  габариты каждого шаблона.

Лоадер — `src/city/mobility/vehiclePayload.ts`. Он кеширует загрузку, чтобы
`MobilityController` и слой поездов использовали один fetch. Ошибка загрузки
не фатальна: остаются процедурные fallback-шаблоны тех же габаритов.

`instanceColor` остаётся белым: ливрея запечена в vertex colors. Выделение
рейса по-прежнему подкрашивает кузов через `instanceColor`.

## Фоновые поезда

`scripts/models/extract_rail_network.py` читает `ground.strokes` с
`k = 'rail'` и `b !== 1`, убирает 64-метровые дубли тайлов по сигнатуре
(концы + длина) и пишет `public/data/mobility/rail/network.json`: 48 самых
длинных участков (≈55 км), каждый — реальный OSM way-кусок.

`src/engine/rail/railTrafficLayer.ts` создаёт 12 составов (на мобильном 5):

- электричка: `commuterLead` + `commuterCar` + развёрнутый `commuterLead`;
- грузовой: `freightLoco` + 6 полувагонов;
- скорости 15 и 10 м/с — модельные параметры, не измерения;
- составы идут без остановок, потому что публичного расписания электричек и
  грузовых поездов нет; это визуальная модель, а не рейсы;
- пауза и переключатель «Vehicles» из HUD действуют и на поезда;
- LOD/отсечение — по прямоугольнику камеры; статистика доступна через
  `window.__CITY_DEBUG__.rail()`.

### Ограничения

- Пути на мостах (`ground.decks`) не включены: в тайлах нет высоты, и поезд
  «поверх моста» выглядел бы хуже пропуска.
- Участки не сшиты через стрелки: поезд заворачивается на конце сегмента.
  Заворот происходит за кадром почти для любой камеры.
- Расписания и остановок нет; составы не выбираются пользователем.
- Это не замена `MobilityLayer`: автобусы/троллейбусы/трамваи по-прежнему
  приходят из проверенных маршрутов и симуляции.
