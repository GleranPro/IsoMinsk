# Деревья: новые кроны и инстансинг — 2026-11-06

## Внешний вид и границы работы

Подготовлены A (цельная гранёная крона), B (несколько объёмов) и C
(асимметричная крона). Варианты сняты в одном движке на одинаковых данных,
камерах и освещении: отдельные деревья, уличный ряд, плотный парк.
Пользователь попросил повторно изучить Warsaw Izo и указал C как допустимую
основу. После просмотра летнего режима референса C выбран по умолчанию;
его плотный уровень получил округлую гранёную крону вместо двух острых объёмов.

Это процедурная стилизация, а не определение реальных пород. Позиции,
количество и номинальные размеры берутся из прежних данных. Сезонный интерфейс,
зимние ветви, снег, мобильное управление и проверка на телефоне сюда не входят.

## Устройство

Матрицы и цвета рассчитываются в worker и передаются как typed arrays.
Стволы и кроны — отдельные InstancedMesh; колёса обозрения — отдельные обычные
меши с независимым материалом. Шаблоны индексированы и разделяются между
тайлами; на плотном уровне одна партия стволов и одна крон, на других — до
четырёх партий всего. Подробная модель C — 56 треугольников на дерево,
далее 44 / 36 / 28. Пороги плотности и ограничение 16 000 сохранены.

Перекраска и скрытие листвы обновляют имеющиеся буферы и видимость, не строят
тайлы заново и обновляют тени. Состояние распространяется на новые тайлы.
При вытеснении освобождаются экземпляры; общая геометрия остаётся до закрытия
стримера. Старый построитель доступен только явно через `?treeStyle=legacy`
для воспроизводимого сравнения.

## Память

Аудит одних и тех же 144 тайлов: **316 704 дерева** в обоих вариантах.
Старые буферы деревьев после объединения: **420 601 248 байт**.
Новые матрицы, цвета и вариации: **50 672 640 байт**; общие шаблоны C:
**10 712 байт**. Снижение **87,95%**, включая CPU-буферы вариаций;
цель не менее 75% выполнена. Это не размер загрузки JSON и не вся память GPU.

Счётчик резидентных буферов приложения включает также текстуры поверхности,
поэтому его нельзя интерпретировать как чистую память геометрии видеокарты.

## Браузерный замер

RTX 3080 Laptop, Chromium ANGLE/D3D11, 1600×900, внутреннее разрешение
640×360, 144 загруженных тайла, 13:00, одинаковые камеры. По одному
последовательному запуску на вариант; это локальный замер, не тест телефона.
Синхронизация с GPU через чтение пикселя; vsync и ограничение FPS выключены.

Полная резидентность: 18,599 → 13,539 с; JS heap: 1020 → 670 МБ.
Счётчик резидентных буферов: 731,20 → 378,42 МиБ. На обзоре draw calls:
422 → 593, видимые треугольники: 4 040 521 → 7 875 933.

**Обзор медленнее на 37,4% по среднему времени кадра.** Инстансинг экономит
память, но новая форма дороже старой четырёхгранной пирамиды: полное число
треугольников деревьев выросло с 3 894 456 до 8 976 604. Поэтому этот этап
не объявляется ускорением всех ракурсов или готовой мобильной версией.
При работе над телефоном потребуется отдельная оценка экранного LOD,
бюджета резидентности и реальных устройств.

Машиночитаемые результаты: [TREE_INSTANCING_2026-11-06.json](TREE_INSTANCING_2026-11-06.json).

## Воспроизведение

```powershell
pnpm run typecheck
pnpm test
pnpm run build
$env:QA_GPU='1'; pnpm run test:e2e
pnpm exec tsx scripts/qa/tree-memory.ts city screenshots/tree-instancing/memory.json
$env:QA_TREE_STYLE='legacy'; node scripts/qa/tree-perf.mjs legacy screenshots/tree-instancing/legacy.json
$env:QA_TREE_STYLE='asymmetric'; node scripts/qa/tree-perf.mjs asymmetric screenshots/tree-instancing/asymmetric.json
node scripts/qa/tree-review.mjs
.venv/Scripts/python.exe scripts/qa/tree-review-sheet.py
node scripts/qa/tree-map-capture.mjs
```

Для другого локального сервера: `QA_BASE_URL` у скриптов, `QA_PORT` у Playwright.
В окружениях с отдельным кэшем браузеров нужен `PLAYWRIGHT_BROWSERS_PATH`.
GPU-замеры проводить последовательно, без правки исходников и HMR во время
измерения; оба запуска принудительно держат 144 тайла через `nolimit=1`.

Локальные изображения: `screenshots/tree-instancing/review/`, включая
`comparison-specimens.png`, `comparison-all.png` и HTML-галерею `index.html`.
Синтетическая сцена сравнения явно отделена от данных OSM.
Реальные парки: `screenshots/tree-instancing/map/`; пары `legacy-*` и
`asymmetric-*` используют одинаковые камеры. Сводный снимок:
`screenshots/tree-instancing/map/before-after-gorky.png`.
